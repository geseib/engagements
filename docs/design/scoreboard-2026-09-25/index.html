Standings: three scoreboard directions

A full-screen stage moment the host opens between rounds. All three share the decided behaviour: Trivia and Call & Answer only; totals as of the last fully scored round (after round 6); each row shows its place change since the previous round (▲n, ▼n, NEW, –); ties are competition-ranked (=4, =4, 6); pages auto-flip, end back on the top page and hold; ← → step pages; Room: 10 per page (default) or TV: 5 per page. 14 players, one with a long name that wraps.

Notes

  • Each board is drawn in a 16:9 stage frame with the stage's tokens, rail and Room/TV ladders (src/src/styles/stage.css), read against the frame so the composition holds at any window size. The strip at the foot is mockup-only: profile switch, reduced-motion switch, replay.
  • Motion follows the stage's contract (__tests__/stageMotion.test.js): keyframes touch only transform, opacity, border-color and visibility, and every animated selector is stilled under prefers-reduced-motion and under ?reduced=1, where the page swap is instant.
  • Add ?fast=1 to any board to run the sequence at about a third of its real timing.
  • Display face: these load Archivo at width 125 from Google Fonts. The app's public/index.html asks Google Fonts for Archivo Expanded, a family it does not serve: asked for alone it answers 400 "Missing font family", and the app's combined request returns Inter only. So the live stage's display type is the system face, not the wide face these boards show.
