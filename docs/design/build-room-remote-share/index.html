Threat model, first draft

The owner's rule: remote reaches the same thing the Wi-Fi share reaches, and nothing more. So the question for each risk is what remote changes compared with the Wi-Fi share as built (plugin 1.18.0).

RiskWi-Fi share todayWith remoteProposed answer
A stranger finds the addressOnly people on the same Wi-Fi can even try it.Anyone on the internet can reach the address while it is up.The address alone opens nothing: no key, the locked page. The address is random and new each time, and never shown or copied; it is used only behind each person's own Open the demo button.
Someone who joined passes the link onOne key for the room; a passed link works for anyone on the Wi-Fi.A passed link would work for anyone, anywhere.A key per person, not per room, minted when they press Open the demo and revocable. The gateway counts devices per key; the host can see "3 devices on one person's link". Removing a player kills their key.
Reaching more of the laptop than the appOnly the ports Claude showed, only from this project's folder (F4).Same gateway, same ports, same folder check.The tunnel points at the gateway, never at the dev server. Nothing new opens.
The dev server's own holes (Vite path traversal, source maps, hot reload)Reachable by key holders on the Wi-Fi.Reachable by key holders anywhere.Unchanged: still only key holders. Keep the gateway's method allowlist and consider blocking /@fs/ and *.map at the gateway for remote requests.
Snooping on the networkPlain http on the Wi-Fi; a key can be read off the air.Better: the tunnel is https end to end.Nothing more. (Wi-Fi stays http, as in LATER.md.)
It stays open by accidentFails closed after 30 s without Engage; only session end closes it.Same rule.The tunnel process is a child of the gateway and dies with it. Off by default every session.
A third party sees the trafficNone.Cloudflare carries it (TLS ends at their edge).Say so in the switch's help line. Owner to decide whether that is acceptable.

Open questions for the owner

  1. A key per person. Stopping a passed-on link means each person's button carries their own key. Worth it, or is one room key (as on Wi-Fi) enough for remote too?
  2. Cloudflare. The free quick tunnel needs no account, but Cloudflare sees the traffic, and the address changes each session. Acceptable, or does it need your own Cloudflare account and domain?
  3. Installing cloudflared. Claude installs it on first use (with the host's yes), or the Connect panel's install step adds it for everyone?
  4. "Here" vs "remote". The phone picks Wi-Fi when it can reach it and remote otherwise. Fine to decide that silently, or should a remote person ever see which route they are on?
