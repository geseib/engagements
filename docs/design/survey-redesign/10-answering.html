Answering on a phone

Five kinds, one player. Each screen is the shipped participant surface (bar, question, dock) with the kind’s control in the middle. The 4px phase strip at the top doubles as progress through the survey. Open any frame on its own to see it full size.

Design notes
Nothing here is new furnitureThe option row (.opt, trivia's), the dock button, the bar, the anonymity line and the counter are all the shipped player's (PlayerSurface.css). New shapes only where no ancestor exists: the scale steps, the yes/no halves, the ranking list.
Chosen is always amber, always filledA picked scale step, a picked yes, a placed rank and a ticked option all use the player's one ‘chosen’ fill (#0F1A2E on #F6A94C, 8.86:1). Pick-several gets a square key and a tick so the shape says the rule before the words do.
Yes / No is not a switchA switch has a default, and a default here is an answer nobody gave. Two big halves, nothing chosen until tapped.
Ranking without dragTap in order, the way the Call & Answer vote already fills its three slots; ↑/↓ to adjust. Drag can be added; it is never required (WCAG 2.5.7).
Saved, visiblyEvery answer is written as it is given. The dock says so, so nobody hunts for a Save button, and a reload resumes on the same question.
Back and NextTwo of the player's full-width buttons side by side — no new button. Optional questions let Next read Skip; required ones leave Next disabled with the reason in the question line.
