Choose a question: one door, one picker, one way back

Owner, 5 Nov 2026: "it seems like a lot of work on the sessions menu to get to pick questions. i had to dig through and then to get back was confusing as well. is there a way to make this easier to navigate?"

What ships on dev (9149c060): the question browser is a step inside the Session menu's Up next tab. The rail's link that reads "Rounds and questions" lands on Rounds so far, which has no questions. Esc goes back one level, a second Esc closes, and a click on the scrim closes everything and forgets the search.

The proposal: one picker, "Choose a question", opened by C or by a door where the host already looks: the rail's Round queue, Your part now's Change what's next, and the Session menu's Up next, which now links to it instead of holding its own copy. It covers the content area only, so the top bar, Your part now and the rail stay where they are. The crumb names where Back goes. Ask next returns you to the round and says what changed, and Esc or ✓ Done returns you to where you opened it from, with focus on the opener. Mockup only; sample content invented.

1 · Today: two screens, mid-round, picking "Pricing we would change" to ask next

  1. The rail's link reads Rounds and questions but opens Rounds so far (ConsoleRail.jsx:185-186). The host then has to find the Up next tab.
  2. The browser is a step inside one tab of a sheet (SessionSetupPanel.jsx:783-912). Clicking another tab drops the step without saying so (:1457).
  3. The way back is a 13px text button, ‹ Up next. Esc goes back one level and a second Esc closes (:467-476), so getting back to the round takes two presses.
  4. Ask next leaves you in the list. The only sign it worked is a "Queued #1" tag on the row. The running order is out of sight.
  5. A click on the scrim closes the whole menu (:1364). Reopening lands on Up next with the search and category cleared, because the sheet unmounts.

3 · The picker open: over the content area, and nothing else moves

  1. The crumb names the way back: "‹ Round 3 · Answer" when it was opened from the round, or "‹ Session menu" when it was opened from the menu. ✓ Done is on the right and Esc does the same. All three close it in one press.
  2. Filters on the left: search, Not asked / All, and the categories as filters with counts. A switched-off category is still listed with its "off" mark, because a filter is not a switch (fork F4).
  3. The list: "The set would serve next" comes first (the next three the set would pick), then every unasked question. Each row has Queue and Ask next. A row that is already queued says "Queued #2" and offers Unqueue.
  4. The preview shows the whole question, its kind and its category, and has the same two actions. Ask now… is in ⋯, with its warning. ↑ ↓ move through the list and the preview follows.
  5. The top bar, Your part now and the rail stay where they are. Space still advances the round, and the rail's queue updates as you queue.

4 · Search and filter: the list narrows, says why, and offers a way out

  1. Typing narrows the list on titles and question text, and the match is marked. Today the search reads titles only (filterRemoteRows, hostRemote.js:441-445).
  2. The active filters show as chips above the list, each with an ✕, plus Clear all. The count says "3 of 23".
  3. When nothing matches, the empty state says so and offers Clear filters. It never says the set is empty (hard rule 6).
  4. The filters and the search are kept for the rest of the session, so a host who closes and reopens the picker comes back to the same list.

5 · After Ask next: back in the round, told what changed, with Undo

  1. The picker closes and the content area shows the round again, exactly as it was.

  4. Focus goes back to the opener (here the rail's Choose a question), so a keyboard host is where they started. Opened with C, focus returns to wherever it was.
