1 · The one host frame: two screens, Call & Answer, answering, with a name request

1366×768, the host's private laptop. The room's window is on the projector. Sam has joined from a new device and asked for their name.

  1. The bell is the Needs-you door. In a live session its number counts only urgent items in this session; things to review later add a dot, not a number.
  2. Your part now sits under the top bar in every mode and type. One orange button.
  3. The Needs-you line is always here at one height, so nothing below it moves. It turns amber with buttons for an urgent item (frame 2 shows it calm). Its buttons are outlined, so the room's next step keeps the only orange.
  4. The same request, on the person. Sam is lifted to the top of People with the same two buttons. People never collapses itself while anyone is asking.
  5. The pulse (session-start D3): the room's count said once, as a number with a bar.
  6. Session menu, one labelled button, top right. Main menu is always top left.

2 · The same frame for Trivia: what stays put, what is the format's

Same laptop, same mode, a Trivia question. Nothing urgent is waiting, so the Needs-you line is calm and the bell shows a dot, not a number, for one Soon item (a late answer). Grey tags mark what is identical in every type. The dashed outline is the only part Trivia supplies, plus the words in Your part now and the pulse's facts.

  1. Same: top bar, Your part now's place and look, People's place, the pulse's place, the loop.
  2. Trivia's own: the options with the live split, and the correct answer, private to the host (the one thing the room must never see).
  3. Trivia's words: "Show the answer" comes from Trivia's own main-button function; People shows points because Trivia scores.

3 · One screen: what the room sees, and where the private things go

Call & Answer on one screen: the laptop is the room's screen. The same top bar and Your part now, slim and public-safe. Sam's request is the same event as in frame 1.

  1. Count only. The bell says 1. No name, no text, on the screen the room reads.
  2. "The room sees this screen" replaces the room's-window status, so the host always knows which mode they are in.
  3. Pressing the bell opens a sheet that leads with the warning and lists items by kind. Each one offers Show on this screen or On your phone.
  4. After Show on this screen, one item, with a blue band saying the room can see it.
  5. The phone Remote is the private half: the same request, named, with the same buttons.

4 · Moving a name to a new device: the participant's side

Sam's laptop battery died; they pick up their phone. Four screens, left to right. The waiting screen updates itself: the phone quietly retries the join every few seconds, so it never relies on the host saying "go ahead" out loud. "Not now" and the ten-minute lapse are described in PLAN §4.4.

  1. Refused, with the real choice. "That's me" is the main button, because a name clash in a live room is usually the same person.
  2. Waiting says what for, and that the host can see it. Ask again appears after a minute.
  3. Granted: in, with answers and score.
  4. The old device is told and stops, so two devices can't answer as Sam.
