Mockups for RATIONALE.md, with the questions I could not settle from the code in OPEN-QUESTIONS.md. Self-contained HTML — no build step, no CDN, no external assets. The generator in _build/ exists so seventeen files cannot drift apart; the output does not depend on it.

The one idea. Participants outnumber hosts by something like fifty to one, arrive on a phone, are often late, and need exactly one thing. Hosts arrive on a laptop and need to sign in. So the root page is not a 50/50 split — it is a phone page for participants that grows a second column for hosts at 900px, and the join side is dominant even at 1280 because the participant is the one who is new, in a hurry, and being watched.
These carry worst-case content on purpose. A 71-character session title with an em dash and an ampersand; a 27-character hyphenated participant name set inside a button; a 58-character email in an error message on a 320px screen; a password failing all five rules at once; a name that collides with someone already in the room. Nothing here was chosen because it fits. Where something does not fit you should see it wrap or the layout change — what you should never see is a string cut off.
Type is not the stage's type. The host spec's ladders are derived for a projected image read at 25 feet and would be absurd here. Body text is 17px, derived twice in RATIONALE §3 — once from the critical print size at a phone held 14 inches away, and once from the 16px threshold under which iOS Safari zooms the page on focus. The floor is 13px and it is for labels, never for a sentence.

Verification

audit.html runs nine checks over every mockup at four viewports — 68 renders, 612 assertions. Three of them were written after they had already failed on this set: E5 found three password fields with no accessible name, E7 found three panels a user could land on with no heading, and E3 measures contrast against the composited background rather than the declared one. There is no projector black-lift model here; these surfaces are not projected, and reusing a number derived for a different display is exactly what the host spec's §7.18 forbids.

The participant path

  1. Root — the code, and a way in for hosts

    The page at / when nobody is signed in. Worst case: 320px wide, where the four code cells and a 48px tap target have to coexist; and 1280px, where the temptation is to give the host half the screen. Press 1–4 in the viewer — this is one file, not two, because a phone version and a desktop version maintained separately drift.

  2. Join — your name, and confirming the code

    Where a QR scan lands (/play?gameId=4821) and where typing a code goes. The session title is here because this beat is the only thing standing between a mistyped-but-valid code and the wrong room. Worst case: the 71-character title, a late arrival at round 2 of 9, and a pre-filled name three characters over the limit.

  3. Join — the code resolves to nothing

    The copy says "nothing is running under 4821", not "that code is wrong", because the server genuinely cannot tell the difference between a typo, an ended session and a deleted one — all three are one 404. Worst case: the error notice added to the tallest column at 320px.

  4. Join — the host has not opened it yet

    Today this is an alert() that throws you back to an empty form. Here you are held rather than bounced: the page polls and lets you in the moment the host starts. The last line says nothing is reserved for you, because nothing is — there is no player record until the session opens.

  5. Join — the session has finished needs a server change

    join-game.js checks !Item and !Item.Started and nothing else, so a finished session still admits people into a dead room. This screen cannot be built until there is a distinct response for it — the exact change is in RATIONALE §7. Drawn anyway, because the alternative is that the gap stays invisible.

  6. Join — private session, access code

    A state that already exists in the code and has no design. Two panels: asking, and getting it wrong. Worst case: an 18-character access code, and the bug where going back today also wipes the name you already typed.

  7. Join — that name is already in the room found while reading the code

    The server keys a player on their name — SK: PLAYER#${playerName}. Two people called Chris are one player, and the second one silently inherits the first one's answers and score. This screen is the only thing standing between that fact and a merged scoreline, and it offers both readings of the collision because both are real.

  8. Join — we could not reach the server found while reading the code

    The state where the participant did nothing wrong, and the copy has to say so without pretending to know whose fault it is. Worst case: three failed attempts, and the 27-character name in a definition list at 320px.

  9. Join — coming back after closing the tab

    Worst case: "Rejoin as Bartholomew Fitzgerald-Chen" set inside a button at 320px, which is where a fixed-height button would clip. Today the rejoin button sets joined = true locally and never asks the server, so rejoining a dead session shows a working game that does nothing.

The host path

  1. Host — sign in

    Three panels: as shipped, credentials rejected, and what the social block becomes if the other three Cognito providers are ever wired into the app. Only Google exists in the code today — the four-provider panel is the variant, not the design. Worst case: the 58-character email echoed inside the error, which is where it belongs and is not where it is today.

  2. Host — create an account

    The approval gate is stated before the form, not in a box halfway down it, and it names the thing you can do instead. Password rules are a live checklist from the first keystroke rather than an error after submitting. Worst case: an email that already exists and a password satisfying three of five rules.

  3. Host — confirm the email address

    Six digits, same cell treatment as the join code, autocomplete= "one-time-code" so the OS offers it, and it submits itself on the sixth digit. Worst case: six cells at 320px, and the resend button in its 47-seconds-to-go state.

  4. Host — registered, and not approved the reason this exercise exists

    A new host's enthusiasm dies here. The redesign does three things: states the gap in the first line, puts a working session-code field on the page because joining is the one thing they can actually do, and gives them a one-tap message to send whoever approves accounts. Gone: the invented "24–48 hours", and the three cards suggesting they go away and think about sessions they might one day host.

  5. Host — password reset, all four moments

    Ask, reset, done, and the Google-account edge. The "done" panel does not exist today — the form drops you on the sign-in screen with nothing said. The second panel's copy is deliberately neutral about whether the account exists; today the app answers "No account found with this email address", which is an account-enumeration oracle.

  6. Host — coming back from Google

    Four panels, two of them the same spinner six seconds apart, because a stuck callback is currently a blank page with a spinner on it for as long as the user is willing to wait. The raw exception text — Authentication failed: 400 {"error":… — moves out of the headline and behind a disclosure.

  7. Host — signed in, but not for this found while reading the code

    Two panels: a host who opened /admin, and a session that expired mid-task. Both are unstyled inline-JSX pages today, and the second branch in App.jsx:117 calls useAuth() inside a click handler, which will throw the moment anyone presses it.

  8. Host — an account an admin made for you

    Cognito's FORCE_CHANGE_PASSWORD. Today it appears with no explanation of why it is being asked. Worst case: a three-character password failing four of five rules, with the primary disabled.

Colours are the Warm Summit tokens from docs/handoff/warm-summit-design-spec.md, with the two text-only tints the host spec added. Red is never used for an error here — it means destructive in this system, and a mistyped code is not destructive. Display type falls back to the nearest system face; production self-hosts Archivo Expanded, which is materially wider.
