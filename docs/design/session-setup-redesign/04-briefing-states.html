Design notes
Two steps, two honest indicatorsReading is a step that finishes (pages and characters come back from parse-document.js:74-79). Writing is one Bedrock call that returns once, so it gets a sweep and an expected time, never a fake percentage (component-library §5).
Scanned PDFs are not an errorpdf-parse returns an empty string for image-only pages and parse-document reports success (:99-108). Under 200 characters of text is treated as ‘no text’: amber, the reason, and the box to type the facts yourself. OCR is an open question, not built.
4 MB, not the 5 MB the uploader claimsFileUploadPrompt defaults to 5 MB (:10) but base64 inflates a file by ~37% and a synchronous Lambda request caps at 6 MB, so anything over ~4.3 MB fails after the upload. It already warns about this (:39-42). The briefing passes maxFileSize 4 MB and refuses before sending.
Long documents are cut, and say wherecleanText truncates at 50,000 characters with a bare ‘[truncated]’ (parse-document.js:144-148). The response grows truncated and pages, so the host is told which part Workie read.
Slides get the way outPDF, Word and text are what parse-document reads (:43-60). A .pptx is refused with how to save it as PDF from each tool — the agenda design’s deck upload uses the same three lines.
One close, one ruleThe shipped dialog discards on X and Escape by design (GameSetupDialog.jsx:357-364). A briefing is minutes of work and a model call, so with one in hand both exits ask first — inline in the foot, never a second modal.
