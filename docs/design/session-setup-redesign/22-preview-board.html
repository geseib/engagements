Preview: both sides of the door

The host looks, edits and steps through with the doors closed; a phone that scans the code meanwhile is told it is not open yet and waits with its name typed; the host presses Open the doors and every waiting phone lets itself in. Open any frame on its own to see it full size.

Design notes
The state modelCreated (closed, not on any stage) → Preview (closed, on the stage: a view, not a stored state) → Open (Started: true, joins accepted, lobby) → Started (round 1 asked) → Ended. The server already stores the first boundary; only the host page learns to show it.
Today the phone just says noA refused join sets an inline error on the join form with the server’s sentence (PlayerPage.jsx:565); the shared-link auto-join swallows it entirely (quiet, :540). joinResult.js already classifies the case as not-started (:89-91); nothing renders it.
Waiting without joiningThe phone polls the public GET /games/{id}, which already returns started (get-game.js:85), every 5 seconds while the page is visible, and joins with the typed name the moment it flips. No join is attempted early, so no player row, no billable session, no roster entry.
The name stays where the rules put itThe name gate sits behind the session gate (session-gate.js:14-21): an unstarted session refuses before it looks at names. Waiting keeps that order — the name is only sent when the doors are open.
Opening is the 7-day clockOpen the doors is start-game.js, which rewrites every row’s TTL to opened + 7 days (:69-97). Preview never touches it, so a session previewed for a week is still on its 90-day unstarted clock (session-ttl.js:13-14).
