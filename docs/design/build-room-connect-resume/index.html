One paste that is always right, whether it is the first time or the tenth

Owner, 18 Oct: "we cant assume they have claude cli running. the nice thing about the first time the command they cut and paste launches claude and starts the session with the key. of course why not just kickoff as well? think through full scenarios." So every case gets a terminal paste that opens Claude Code in the right folder and runs /engage:kickoff. Kickoff now connects first and knows a resumed room from a new one, so the host never chooses between kickoff and continue.

No key in the paste. The folder saved its key when Claude first connected (.engage/session.json), so coming back never mints a new one, and the key already working keeps working.

  • The folder is reported by the plugin relative to the home folder (~/build-room/volunteer-sign-up), never the full path with the laptop's user name. A folder outside the home folder is shown by its name only, with "cd into it first" instead of the cd.
  • Kickoff on a resumed room does not post a new plan. It restates where things stand in one update, picks up the host's latest direction, and carries on.
