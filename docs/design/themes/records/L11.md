# L11: `.ui-row` (CSS only)

A new CSS-only mixin, `components/ui/Row.css`: hover and selected states for a list or
table row, reading `--row-hover`, `--row-selected` and `--select-mark` only. No screen
adopts it in this phase.

## The component

| | |
|---|---|
| Class | `.ui-row` on the row element a surface already has (`<tr>`, `<li>`, `<a>`, `<button>`, `<div>`) |
| Hover | `background: var(--row-hover)`, never on a selected row |
| Selected | any of `.is-selected`, `aria-selected="true"`, `aria-current` (not `"false"`): `background: var(--row-selected)` + `box-shadow: var(--select-mark)` |
| Table rows | a `<tr>` paints its `td`/`th` (cells here usually carry their own background, and a `<tr>` box-shadow is not drawn everywhere); the select mark goes on the first cell only. Anything else paints itself. The two selector families never match one element, so a tint is never laid down twice. |
| Declares | `background` and `box-shadow` only: state, never layout |
| Fixture | `components/ui/fixtures/Row.jsx` (dusk and paper; a table with an `aria-selected` row, a nav with `aria-current`, a list with `.is-selected`) |

SPEC ambiguity resolved: SPEC §6 names the component `RowSelect` "(CSS-only mixin class
`.ui-row`)" with no state hook. I accept all three selected forms above, because the ~25
scoped copies it replaces select by `aria-current` (AdminShell nav), by a class, or by
`aria-selected`; an adopter should not have to change its markup. `aria-current="false"`
counts as unselected (and, as a side effect of keeping the hover selector simple, gets no
hover: the record says to write no `aria-current` on an unselected row).
