# L13: Modal look (`.ui-dialog`, `.ui-scrim`)

A new stylesheet, `components/ui/Dialog.css`: the look of the one modal shell. Behaviour
stays in `components/Modal.jsx`, which renders its overlay and content class names
verbatim, so an adopter passes `overlayClassName="ui-scrim"` and
`contentClassName="ui-dialog …"`. No screen adopts it in this phase.

## The component (class API)

| Class | What |
|---|---|
| `.ui-scrim` | fixed, full viewport, `--scrim` ground; **flex-start + overflow-y: auto + padding** (hard rule 10); `z-index: var(--ui-scrim-z, 60)` |
| `.ui-dialog` | `margin: auto` card, `width: min(560px, 100%)`, `--surface` / `--text`, `1px solid --rule-strong`, `--font-ui` at 15px, `overflow-wrap: anywhere` |
| `.ui-dialog--small` / `--wide` / `--full` | 440px confirm / 760px table+form / 920px full-height: flex column, `max-height` in `vh` then `dvh`, body scrolls (`min-height: 0`), head and foot `flex: none` |
| `.ui-dialog-head`, `-titles`, `-title`, `-sub` | head row; title in `--font-display` / `--display-weight` / `--display-tracking` at 19px; sub in `--muted` at 13px |
| `.ui-dialog-x` | 32px close target, `--muted` → `--text` on `--row-hover`, focus ring `2px solid var(--text)`, disabled state (the "deliberately dead while in flight" X, hard rule 2) |
| `.ui-dialog-body` | padding only |
| `.ui-dialog-foot` | the bottom exit row, `border-top: 1px solid --rule`, wraps, right-aligned by `margin-left: auto` on the first child (hard rule 9), never `justify-content: flex-end` |

Layout passthroughs an adopter sets from its own scope to keep its geometry (all read with
a fallback, none declared here): `--ui-scrim-z`, `--ui-dialog-radius` (default `--radius`),
`--ui-dialog-shadow`, `--ui-dialog-t-head/-body/-label` (19/15/13).

Fixture: `components/ui/fixtures/Dialog.jsx`: default and `--small` in dusk and paper, and
`--full` in dusk; scrims pinned with inline `position: absolute` inside fixed-height
frames so several sit on one gallery page; no `<Modal>` (it would lock the gallery's
scroll and trap focus).

SPEC ambiguities resolved:
1. **Radius.** SPEC §6 says the look reads `--radius` (16px); today's console modals are
   12px (`.qsets-modal`, `.evts-modal`, `.evb-modal`). I read `--radius` by default and
   expose `--ui-dialog-radius`, so an adopter keeps 12px with zero Classic delta, or takes
   16px as a recorded delta. Adopting units decide.
2. **Shadow.** Today's modals cast `0 24px 64px rgba(0,0,0,.5)`. Black has no role and the
   gate is 0 for new files, so the default is the dusk shade channel,
   `rgb(var(--shade-rgb) / .5)` (navy `15 26 46`, not black). An adopter that must be
   pixel-identical sets `--ui-dialog-shadow` from its own (allowance-counted) scope.
3. **Border width.** A fixed `1px`, not `var(--hair)`: `--hair` is 2px under the Call
   profile, which would change a dialog's box size on the stage (a layout change).
4. **Theme.** The sheet sets none. A dialog must carry `data-theme` (or sit under one);
   otherwise it inherits `<html data-theme="light">`, i.e. paper (README "Lessons from
   Phase 0"). Stated in the header.
5. **Scope of "look".** SPEC lists only scrim and card. I added the head/title/sub/X/body/
   foot parts because hard rule 2 (an X and a bottom exit on every dialog) is a look as much
   as a behaviour, and the twelve shells each re-cut them. No button styling: that is L3.
