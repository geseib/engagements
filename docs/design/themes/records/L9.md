SPEC ambiguities resolved here:
- **The wall's theme.** `--wall-canvas` is declared only for dusk, so a wall under a paper ancestor would carry navy `--text` on the dusk canvas. The wall variant therefore always sets `data-theme="dark"`.
- **Call for the wall.** `roles.css` flattens `--field` under `:root.d-call` but not `--wall-canvas`; PLAN L9 asks for flat under Call in both skins, so `Ground.css` flattens both variants itself. The Presentation today selects Call with `.present[data-profile="call"]`, not `:root.d-call`, and its canvas is not flattened (only `.present-wipe` is). Phase 2 decides whether the wall adopts the `:root.d-call` rule or Ground gains a profile hook (a frozen-library change, so a mini-unit).
- **`data-surface="wall"`** is not set by Ground: the wall rule (`--action`) is the caller's (PresentStage, and the host stage only while projected), SPEC §3.
- **Not reproduced:** the stage `.field`'s amber horizon and ridge silhouette (`styles/stage.css` `.field`, `.field::after`). No role holds those literals; W5-a, adopting Ground on the stage, keeps its own `::after` or records a delta.
