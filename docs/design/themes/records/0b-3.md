**Codemod autos refused (a tool finding):**
1. *Self-reference.* The codemod proposed `var(--X)` for a declaration **of** `--X`:
   `styles/stage.css` `:root { --rule; --success-text }` and `.stage { --bg; --surface;
   --surface-2; --text }`. A custom property that reads itself is a cycle and invalid at
   computed-value time, which would have dropped every stage border and the stage's dusk.
   `:root --rule` became the channel `rgb(var(--slate-rgb) / .22)` (identical in both skins,
   and it keeps paper `--rule` off unthemed dusk scopes); the others are keeps.
   `scripts/skins/codemod.js` should refuse an auto whose replacement names the property itself.
2. *Wrong theme ancestry.* `.gsd` (GameSetupDialog) has no `data-theme`: Modal owns its content
   element and GameHostPage mounts it outside any dusk root, under `<html data-theme="light">`.
   The codemod (and classicEquivalence) check against the theme passed on the command line
   (dark), so they rated `--gsd-card → var(--surface)`, `--gsd-field → var(--surface-2)`,
   `--gsd-text → var(--text)`, `--gsd-success-text → var(--success-text)` "Classic-identical";
   in the browser they would resolve **paper** (a white dialog in Classic). Refused, kept. Every
   other auto was checked against its real root: `.brm`, `.plr`, `.scard`, `.hea`,
   `.ag-stage-root`, `.hr` carry `data-theme="dark"`; `.brc`/`.bpl`/`.fbr`/`.bwh` sit inside
   them; `.mcmp`, `.sb`, `.svw` sit in `.stage` and only received theme-invariant forms.
