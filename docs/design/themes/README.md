# Site skins: how to run the migration

For the **coordinator**: the agent (or person) who hands units to workers, merges them, and
keeps the record. Workers read `WORKER-CHECKLIST.md`, not this.

| File | What it is |
|---|---|
| `SPEC.md` | the design (approved 2026-10-13) |
| `PLAN.md` | phases and units, in prose |
| `units.json` | PLAN as data: every unit's files, styles.css ranges, themes, components, routes |
| `INVENTORY.md` | the counts at the start (16e8c3dd); re-derive with `measure.js`, never edit |
| `WORKER-PROMPT.md` | the worker prompt template (filled by `prompt.js`) |
| `WORKER-CHECKLIST.md` | the ten steps a worker follows |
| `records/<unit>.md`, `records/<unit>*.decisions.json` | one record per unit, written by its worker only (`TEMPLATE.md`, `EXAMPLE-ScoreCard.md`) |
| `PROGRESS.md` | generated by `progress.js`; never edited by hand |
| `shots/` | screenshots (git-ignored) |

## The tools (`scripts/skins/`, each has `--help` and `--selftest`)

| Tool | Does |
|---|---|
| `measure.js` | every count in INVENTORY (`--ref 16e8c3dd` reproduces it exactly), per file, per SC unit, JSX |
| `deadSelectors.js` | live / unsure / dead per class of a sheet or SC unit |
| `codemod.js` | `--report` proposals + a decisions file; `--apply` once every decision is filled; `--tokens-only` for 0b |
| `classicEquivalence.js` | resolves every declaration of base and head under Classic and compares: the primary gate |
| `shoot.js`, `diff.js` | screenshots at 375/660/1280 (+1920 per profile for the Presentation) in each skin, side-by-side index; pixel diff vs a baseline |
| `harness.js` | what a role resolves to, and from where; the harness self-test against SPEC §4 |
| `retarget-tests.js` | Phase 0a: moves 313 `token(GLOBAL_CSS, …)` reads in 42 palette tests onto the harness |
| `seed-allowances.js` | writes the allowance pragmas at measured counts; refuses to raise one |
| `prompt.js` | `--list` units, `--check` ownership, `--unit X` a paste-ready worker prompt |
| `progress.js` | rolls `records/*.md` into `PROGRESS.md` with fresh totals |

Shared code: `src/src/testing/skinScan.js` (the scanner, read by the jest gate and every tool) and
`src/src/testing/skinHarness.js` (role resolution for tests). Tests: `__tests__/skinLiteralsPalette.test.js`
(the gate), `__tests__/skinHarnessPalette.test.js`.

Self-tests, all at once (each exits 0; with `--plant` each must exit 1):

```bash
for t in measure deadSelectors harness retarget-tests seed-allowances codemod classicEquivalence diff prompt progress shoot; do
  node scripts/skins/$t.js --selftest >/dev/null 2>&1 && echo "ok   $t" || echo "FAIL $t"
done
```

(`shoot` needs `src/dist`: `cd src && npm run build` first.)

## Run one unit end to end

1. `git checkout -b working/skins-integration` once; every wave starts from its head. Note the
   sha: that is the unit's `BASE_REF` (the wave-start ref).
2. `node scripts/skins/prompt.js --check` (must pass), then
   `node scripts/skins/prompt.js --unit W3-b --base <sha> --worktree <path>`.
3. Paste the output as the prompt of one Agent call (one worker per unit, its own worktree:
   `isolation: "worktree"`; check the worktree has `src/node_modules/.bin/jest`, and never let a
   worker `npm install` — memory "running the suites").
4. When it reports back: read its record, its decisions file (every `keep:` has a reason, every
   Classic delta has one), and its shots index.
5. Merge its branch into `working/skins-integration` (serially, one unit at a time), then re-run
   the gates there: `cd src && CI=true npx jest && npm run lint && npm run build`, all of
   `tests/*.js`, and `node scripts/skins/classicEquivalence.js --base <wave-start sha> --unit W3-b`.
6. `node scripts/skins/progress.js --write`, commit `PROGRESS.md`.
7. Collect accepted Classic deltas and foreign assertions from the records; hand foreign
   assertions to the owning unit (or do them yourself between waves).

## Run a wave

- Units of one wave own disjoint files (`prompt.js --check` proves it against today's tree). Start
  them all at once from the same `BASE_REF`; merge them serially; re-run gates after each merge.
- A wave starts when the previous one is merged (later waves read what earlier ones settled).
- Before Phase 0a lands, `codemod.js --apply` refuses on the real tree (there is no
  `styles/roles.css` to resolve `var(--rule)` against). Phase 0a is therefore the first unit
  and runs alone; then 0b-1..4, 0c, 0d in parallel; then 0e.
- Present is not on until Phase 0d's setting. Until then `shoot.js` forces `data-skin` (the
  index says so) and, before 0a, Present renders as Classic.
- Before Phase 8, the owner signs off after Phase 0 (flip on dev and back), after P2 (the
  Classic Presentation), and before the flip on test. A branch push to `dev` is a deploy
  (CLAUDE.md): only the coordinator pushes, only the integration branch, only when asked.

## Screenshots

`shoot.js` serves `src/dist` locally with a stub `config.js` (`API_BASE` = `/__api/` on the same
server) and answers the API from `scripts/skins/fixtures/shoot/` — no tier is ever called.
Routes: `routes.json` lists the public pages and the six Presentation moments (lobby,
answering, voting, tally, navigator, read). Signed-in surfaces need the gallery (below) or an
owner walk on dev (memory "Viewing the stage": Google sign-in passes through in the Browser pane).
A full public + Presentation run (156 shots, both skins) takes about 6 minutes.

Baseline for `diff.js`: the worker shoots before changing anything
(`--out docs/design/themes/shots/<ID>.base`, checklist step 2), then after, and diffs Classic.
Two runs of the same build diff to 0 pixels on every public page and every Presentation
moment but one (checked when the tooling landed: fixed port 4719, reduced motion, animations
disabled, fonts awaited, a refit after fonts): `/present` navigator at 1280 differs by ~15 px
(the canvas fit settles a mini card's border a sub-pixel differently). Diff Presentation shots
with `--tolerance 32`; everything else at 0.

## Gaps found in the SPEC (for Phase 0a to decide)

1. **Two channel roles are missing.** 32 `rgba(15,26,46,a)` (dusk scrims and shadows) and 8
   `rgba(244,237,228,a)` (warm-text tints) have no Classic-identical role form, so their files
   cannot reach allowance 0 without a Classic delta. Proposed: theme-invariant `--shade-rgb: 15 26 46`
   and `--glow-rgb: 244 237 228`. They are in the fixture (marked PROPOSED) and the codemod
   uses them only if `roles.css` declares them. (57 `rgba(255,255,255,a)` are legacy white tints:
   decide per unit.)
2. **A skin value must read only `--sk-*` values, never a role.** `--sk-dark-eyebrow-color:
   var(--muted)` resolves on `<html>`, whose `data-theme` is `light` (`public/index.html:2`), so
   dusk gets the paper muted. Write `var(--sk-dark-muted)`. Likewise Present's field gradients:
   `var(--sk-dark-bg)`, not `var(--bg)`. `harness.js --selftest` demonstrates it; the 0a
   `skinPalette.test.js` should assert it.
3. `--accent-text` on paper is `#9A5B18` in Classic; every paper `color: var(--primary)` that
   becomes `accent-text` is a Classic delta. Paper units should prefer `accent` for marks and
   record copy deltas, or the owner accepts them in a batch.

## Proposal: the dev-only skin gallery (SPEC §5.3; not built, needs the owner's yes)

A route `/dev/skins`, mounted only when `window.ENV === 'development'` and `?gallery=1`, and
excluded from the production bundle by a `process.env.NODE_ENV !== 'production'` guard around a
dynamic import. It renders every `components/ui/*` component in every variant, and fixture
mounts of the presentational surfaces that take a model as props (`PresentMoments`, the
`Scoreboard` looks, `ScoreCard`, `SurveyResults` kinds, `QuestionPreview`, `RoundReport`,
`TallyRow` lists, admin panels with a mocked `adminApi`), each in an element with a fixed id
(`#gallery-<id>`). `shoot.js` then gains `--gallery`: `gallery:<id>` routes in `units.json`
become `/dev/skins?gallery=1#<id>` shots of that element. Each wave unit adds its surface's
fixture mount as part of its work. Cost: one route branch in `App.jsx`, one lazy chunk, no
backend. Until then, signed-in surfaces rely on `classicEquivalence.js` plus an owner walk.

## Lessons from Phase 0 (coordinator, 2026-10-13)

- **Check the theme the element really sits under.** `codemod.js` and `classicEquivalence.js`
  judge only the theme passed with `--theme`. An element with no `data-theme` of its own (a
  dialog such as `.gsd`, portaled modals) inherits `<html>`'s `data-theme="light"`, so a role that
  looks Classic-identical under `--theme dark` renders paper in a browser. 0b-3 caught four such
  grounds by hand. Pass `--theme both`, or the light theme for anything that can mount under
  paper, and say in the record which theme each scope renders in.
- **The codemod no longer proposes a custom property as a read of itself** (`84e3402c`); 0b-2
  and 0b-3 each refused such proposals by hand.
- **Shot noise.** Repeated shoots of the same build differ by a few dozen pixels on the response
  navigator and on anti-aliased text. Judge a diff by its images (a colour region versus glyph
  edges), not by the count; computed-style comparison is the stronger proof.
- **Ports.** Parallel units collided on the default shoot port 4719; give each unit its own
  `--port`.
