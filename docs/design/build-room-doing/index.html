D6 · The rules

Two sources, one line. The line Claude states wins while it is fresh; otherwise the in-progress item on Claude Code's to-do list is read by the plugin's hook after each tool call.

B · Claude says itAt the start of each piece of work, through the plugin: doing and done forms, 4 to 7 words
A · Claude's to-do listThe in-progress item's present-tense form, read by the PostToolUse hook

Host, Stage, devicesThe line, and how long
HistoryThe done form, when the line ends
RuleDecisionWhy
Length4 to 7 words, at most 50 characters, as Claude wrote it. Longer is cut at the last whole word that fits, with no ellipsis. Under 2 words is ignored.It has to read from the back of the room and fit the header chip at 1440 wide.
FormStarts with a verb ending in -ing: "Scaffolding the site". The screens add "Claude is" and lower-case the first letter. A to-do item already has this form (activeForm).One grammar on every screen; the screens never edit Claude's words beyond the first letter.
Past tense (History)B: Claude gives it, with the line ("Scaffolded the site"). A: the plugin derives it from the -ing form with a short list of irregular verbs; when unsure it shows "Done: Scaffold the site", the to-do item's own words.Asking costs Claude one more field, once per piece of work. Deriving "Setting up" or "Building" by rule is easy to get wrong.
Which source winsB wins until Claude states another line, waits for direction, or 15 minutes pass while the to-do list moves on. Then A.Claude's own line is the better one, but a forgotten one must not sit there all afternoon.
When a line endsClaude states a new line, the to-do item is marked done, or Claude waits for direction. The ended line becomes a History entry with its duration.Every end is an event the plugin already sees.
StaleNo command and no post for 3 minutes, and not waiting: "Claude was …", with "last seen 4 min ago" on the Host screen only.Today's 90-second building window is too short for a long install or a helper's research.
Room-safeShown: Claude's own words about the work.
Never: file contents, file names or paths, commands, code, web addresses, people's names. The server drops a line containing /, a backtick, @, :// or a file extension, and the screens fall back to the next source.		The line is written by Claude, so the plugin's instruction is the first guard; the server check is the second. A name cannot be caught by rule, so the instruction says so plainly.
CommandsHost screen only, folded, small type, the last twelve, repeats grouped ("Ran git remote, 6 times"). Never on the Stage, devices or in History.They are useful for the host to see Claude is alive; they are noise to the room.
HelpersOne helper line under Claude's, from the helper's own stated line. Two or more: the newest, and "and 1 more helper".The room sees that research is happening without a list.

Open questions

  1. Past tense for the to-do list source: derive it ("Building" to "Built") with an irregular-verb list, or always show the to-do item's own words ("Done: Build the bar chart")? Derived reads better; the item's own words are never wrong.
  2. Helpers on the wall: should the Stage and the room's devices show the helper line, or keep it on the Host screen only and show just Claude's line to the room?
  3. Commands folded or open: folded by default for every host, or open on the first session and remembered after that?
