A team invite stays in view until it is answered

Owner, 2026-10-10, from a reviewer: the invite showed only near the top of the dashboard, and was lost while they made their first Build Room. One quiet blue line, on every screen the invited person works in, never on a screen the room sees. Never orange.

Checked in the code, before anything here is built. (1) Accepting does not approve anybody. admin/orgs/accept-invite.js writes the MEMBER row, the user's reverse row, deletes both invite rows, sets defaultOrgId if unset, and flips a personal org to a team. It never calls Cognito; the account's groups are unchanged. Only admin/manage-users.js moves pending → hosts, and only for the platform admins group (shared/require-admin.js). (2) Today a pending person cannot even see the invite. auth/authorizer.js:450-453 gives GET /invites and POST /invites/{token}/accept to ['hosts','admins'] only, so both answer 403 on either waiting screen, and PendingInvites stays silent by design. (3) There are two waiting screens. New sign-ups are in the pending group and see auth/PendingApproval.jsx ("Your account exists. It cannot host yet."). The App.jsx "Access Pending" block (lines 160-175) is reached only by a signed-in account with none of pending, hosts, admins. P1 draws the first; the second gets the same row. (4) There is no Decline. No route exists; only the team's admin can revoke (revoke-invite.js). Decline below is proposed. (5) Invites last 14 days (INVITE_TTL_DAYS); the list hides expired ones on read; daysUntilExpiry rounds up, so today's row says "1 days left" on the last day.

Open questions for the owner

  1. Show invites to a person still waiting for approval? Today the authorizer refuses them both invite routes. Allowing pending on GET /invites and the accept route is safe on its face (the handler matches the caller's verified email), but it is a deliberate change to a block written to keep pending out.
  2. Should accepting an invite approve the account? Today it does not: the person joins the team and still cannot host until platform staff approve. If yes, any team owner or admin can in effect approve hosts on the platform (and the team's plan then pays for them). P1 draws both lines.
  3. Decline: add it? It needs a new route (POST /invites/{token}/decline, deleting both rows as revoke does). Does the team's admin see "Declined" in their Invited list, or does the line simply go?
  4. A or B in the Build Room? Recommended A: the problem was a notice that got lost, and a dot is the easiest thing to stop seeing. A costs one 42px line on the Host screen only, for at most 14 days.
