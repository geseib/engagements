Starters for a room that builds with Claude

A starter is a small working web page Claude lays down at the start of a session, so the room sees something running in the first minutes and spends the hour shaping it. Every one works with no internet and no install, and each one is filled by the room’s ideas, votes and ratings.

Plain web pagesHTML, one stylesheet, a few small libraries copied in. Runs with one command, shares over Wi‑Fi or remotely as it is.
Kept in this repoA public folder on GitHub. Each site serves its own copy, and the plugin checks every file before writing it.
Host picks in the openingOn “What are we making?”: pick a group, then a starter. “None” is always first.
Room adds sources“Add a source” on the phone: a link to a page, a repo or a CSV. Nothing downloads until the host says use it.

How a starter gets there

  1. The host picks it in the opening; the room’s brief says which.
  2. Claude asks the plugin for it. The plugin downloads it from the Engage site and checks every file against a fingerprint it carries. Any mismatch and nothing is written.
  3. It goes into a fresh project as the first commit, so the room’s first decision is a clean change against it.
  4. Each one carries a map for Claude (CLAUDE.md), sample data in demo/data/, and “replace me” markers Claude fills from the brief.
  5. Anyone outside a session can copy one: npx giget gh:geseib/engagements/src/public/starters/dashboard

How the room adds content

  1. On the phone, Add a source: a link and one line on what it is. “Only links anyone may see. No personal data.”
  2. It lands in the host’s ideas list. The host presses Use this, or doesn’t.
  3. The plugin (not Claude) downloads it: secure links only, no addresses inside the network, 10 MB at most, data and image files only. It goes into a hidden inbox folder.
  4. Claude says what it found (“Monthly visits by branch, 84 rows: fits the line chart”) and flags columns that look like personal data.
  5. Only after the host sends it on does the file join the page, with a line in SOURCES.md.

Works for a web page, a CSV or JSON link, a file in a GitHub repo, and a Google Sheet published as CSV. Anything fetched is treated as data, never as instructions to Claude.

Left out, or folded in

  • Calculator: a mode of the “what if” simulator.
  • Scroll-driven story: the infographic’s story mode.
  • FAQ finder: lives inside training and the branching story.
  • Story map: waits on a map that works offline; the free map provider’s terms forbid offline use.
  • Journey map / persona: a good design-sprint add-on later.
  • Sound toy: fun, but niche and loud in a room.
  • Personality quiz: a light opener; easy to add later.
  • Team page (“Manual of Me”): parked; it names people, which Build Room avoids, so it needs a privacy design first.
  • Interactive website: replaced by the clickable prototype.

  2. One made-up subject (a town library) for every sample page, or two or three Claude can choose from to match the room?
  3. Does the room vote for the starter, or does the host pick it?
  4. Budget balancer and decision matrix are best when every phone’s sliders are averaged. Worth a new question type, or one rating per criterion to start?
  5. Photo uploads from phones soon, or are links enough for now?
  6. Allow PDFs as sources (good for training content, big and hard to review)? Is 10 MB the right cap?
  7. Google Sheets only as published CSV links, or read private sheets with the host’s sign-in (much more work)?
  8. A fifth first-wave starter for a plain document or guide page?
  9. Keep starters in this repo, or a separate public repo from day one?
