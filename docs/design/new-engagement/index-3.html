3-A1

Option A — one layout, open: the form and “How it runs”

No modes. The dialog always has the same shape: the form on the left and the walkthrough on the right, open by default. The only control is “Hide”, on the walkthrough itself, so it says exactly what it changes. Gallery or chips depends only on whether this host has created before; nothing else differs between hosts.

Dana sees what happens before she commits, with no toggle to understand. Sam hides it once and never sees it again. Owner: the walkthrough is on screen from the first open, and nothing called “Guided” or “Quick” needs explaining.

3-A2

Option A — one layout, hidden: a labelled rail

Hidden, the pane folds to a 56px rail that still says what is in it: “How Call & Answer runs”, with the format name updating as the chips change. One click (or Enter on the rail) brings it back. Hidden or shown is remembered. The dialog keeps its size; the form takes the space.

Sam: zero teaching on screen, the same keyboard path as before. Dana: if she hid it by accident, the rail tells her what she hid and how to get it back.

3-B

Option B — the form alone; “How it runs” opens under the format

A single-column form. The format’s plain line ends with “How it runs ▾”, which opens the walkthrough as an accordion inside the Format step (drawn open). Nothing is beside the form, so the dialog is narrower.

Sam is happiest: nothing appears unless asked. Dana has to notice a small link to find the most useful thing on the page. The open walkthrough pushes Questions down, so the form moves under her while she reads. Owner asked for the walkthrough to be seen; this hides it by default.
