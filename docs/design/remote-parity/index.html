The Remote does what the host screen does: names, and Workie's pages

Owner, 2026-10-12, running a Call & Answer session from the Remote on a phone. Two gaps. The Remote lists players but cannot act on them, and never shows a request to take a name. And the projector pages Workie's read-back, but the phone cannot turn those pages; its big button skips them.

A · Names: Unlock, Let them take it, Not now, Lock again, Remove, Bring back

Every route already exists and already lets the session's host call it from any device. The Remote polls GET /players every 6 seconds, and that reply already carries each name's handover state and the removed list. The Remote throws both away (config/hostRemote.js:722-743). The fix is screens, not servers.

A1 · A request arrives while a round runs

Someone on another device asks to take Priya. The strip sits above the round, under the bar, and stays until somebody answers it, here or on the host screen. Both answer buttons are plain; Close answers keeps the one orange. Space never answers it, because there is no Space here, and a stray thumb on the primary must not either: the strip is above the status card, the primary is at the foot.

B · Workie's pages, turned from the phone

The proposal makes the page a fact on the round's record, the way the beat and the spotlight already are, and lets the phone send next or back. The projector does the arithmetic, because only it knows how much text fits on its wall.

D · A host note, at any time

Players comment through POST /games/{id}/comments (comments.js:332): only a joined name, only while the room is on that round's results, about the summary, the results or one response. The rows land per round in both reports under Comments (create-report.js:250-273, GameReport.jsx:375) and in the room's feedback panel. A host note is the same row, written by the host's own door: signed in, any phase, any round the session has played, and marked as the host's.

D1 · Writing one, mid-round Recommended

Add a note sits beside Players on the round view, in every phase. It opens a sheet over the lower part of the phone. The round is the one on the wall unless the host picks another. During a round's answers there are no results yet, so the note is about the question; after, it can be about the results, Workie's read or one response, as a player's is. Post note is the one orange; the dock's primary is covered while the sheet is up, so it cannot be pressed by mistake.

Open questions

  1. Should the host screen gain Not now and Lock again too? Today they are wired only in the Build Room. Recommend yes: two props on PlayersList in SessionSetupPanel, same route, and it stops the phone offering a verb the projector does not have.
  2. Should the host screen show the request strip outside the Build Room? In Call & Answer a request is visible only if the Players tab happens to be open. Recommend yes, a one-line strip above the dock, never on the stage the room reads, since it names a person.
  3. Who wins when both screens answer one request? The server, first write. A late Let them take it after Not now gets 409 "Nobody has asked"; a late Not now after a grant gets 409 "already changed". Recommend the Remote show that sentence and re-read the roster at once. No locking.
  4. Roster poll on the phone: keep 6 s? A request can sit unseen on the phone for up to 6 s. Recommend keep 6 s; the asker waits on a person anyway. Re-read at once after any action.
  5. Remove: confirm or undo? Recommend undo (A3). Removal is reversible and keeps everything; the host screen does not confirm either.
  6. Paging: a new route, or the beat's route? Recommend extending POST /stage-beat with step and the stage's notesPage/notesPages, stored on the same ROUND# record. No new function (the stack is near its 500-resource ceiling), no template change.
  7. Who counts the pages? Recommend the stage: pages depend on the wall's display profile, which only the host page knows. The phone sends steps, never page numbers.
  8. Show the page's text on the phone, or only "Page 2 of 4"? Recommend the text (B1): the host can read along without turning round. Needs the stage to publish its profile so the phone cuts the same page.
  9. Should the scores' answer pages (RESULTS) be pageable from the phone too? They share the index on the host page. Recommend not now: same mechanism later, keyed by phase, once Workie's pages have been used in a room.
  10. Show the question's Background on the Remote? The 2026-09-25 decision kept Background for Workie and admins, and put only the "Workie had" hint on the Remote. Recommend yes for the session's own host, on the Remote only, marked private: it is the person who will be asked to "tell them more". Needs /host-state to add it; the public /state must never carry it.
  11. Show a trivia answer on the Remote before Results? /host-state is host-gated but shares a body with the public /state, which hides the answer until Results. Recommend yes, added only on the host branch, with a test that the public body never gains it.
  12. Host note: a new route or the player route? The player route is public and checks a joined name and the round's state; the host's note needs neither and must be signed in. Recommend one new Cognito event on the existing comments function, POST /games/{id}/comments/host, checked with callerMayDriveSession. No new function; about two stack resources.
  13. Does a host note reach the room? The owner said it goes into "feedback discussion segments". Recommend: a switch, on by default while that round's results are up, so the note shows in the room's feedback panel labelled Host; off, reports only. Never on the wall by itself: the host can Feature it like any comment, and it shows as "Host" on the wall.
  14. Can a host note be deleted? There is no delete for any comment today. Recommend not in the first version; add a host-only delete with the audit write the delete rule requires (owner, 2026-10-04) if hosts ask for it.
  15. A new anchor for "the question"? Players comment on the summary, the results or a response. A note during answers has none of those. Recommend adding question to the closed set, in every copy at once, and the host route the only writer of it.
