Design notes
Full by default, the owner's callOwner, 23 Sep: ‘allow seeing full report. with an option to turn this off, so the report is not shared, or is only anonymous.’ One setting, three values: Full (default), Anonymous, Not shared. The event's default is chosen when it is made (05) and set here; each item can differ.
Anonymous is removed by the serverWhen an item ends the stage saves two PDFs: today's full one, and one rendered from GET /games/{id}/report?view=anonymous, whose payload already has every name replaced — standings, answers, voters, a featured comment's author. Nothing is hidden with CSS, so a download can never carry a name the setting took away.
Names can go, not come backPhones said ‘with names’ at join (p-01). So once anyone has joined, Full can become Anonymous or Not shared, and Not shared can become Anonymous, but nothing becomes Full that people were not told about. Item 4 (‘What's slowing us down?’) was switched to Anonymous after the room got candid.
Surveys never carry namesA survey item offers Results or Not shared: its shared results are the survey design's frozen, nameless copy whatever its Names setting (survey-redesign/RATIONALE.md §3). A presentation's reference copy follows the switch set when it was added (04), and can be changed here.
Both standings, as the owner askedDecision 6: ‘both’. Each scored item keeps its own standings (in its report); the day's are the sum of every scored item's final points — trivia, and Call & Answer's placement points. Surveys, polls, wavelength, talks and breaks add nothing. Copied onto each attendee's row when an item ends, so they outlive the 7-day sessions. The table shows names because this event's reports are Full; under Anonymous it would show Player N.
Keep reports for a yearDecision 10: only the saved reports are kept for 365 days (permanent/, as save-report.js does). The event rows and reference copies still go 90 days after the event.
Built from saved reportsSession rows expire 7 days after start (session-ttl.js:29-30). Each item keeps its REPORT# keys (save-report.js:161-182, 90 days, 365 if kept); this page reads those. Item 7's PDF did not save; the data lives 30 days (create-report.js:911-916), so the row offers the save rather than pretending.
