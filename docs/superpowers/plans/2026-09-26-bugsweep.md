### Task 1: Host-only session fields leave the public `GET /games/{id}`

**Bug (high, security).** `GET /games/{gameId}` has no authorizer
(`template-clean.yaml` ~2117–2123: `GetGameEvent`, HttpApi, no `Auth`). It
must stay public, because every phone calls it. With `?role=host` the handler
(`lambda-functions/game/get-game.js` from ~line 122) returns
`aiContext: sessionMeta.AIContext` (~136) and `briefing: sessionMeta.Briefing`
(~151), both DECRYPTED. Both are encrypted at rest per org
(`tenant-crypto.js` ~283). So anyone who knows a 4-digit code can `curl` a
team's private Workie context and Call & Answer briefing. `role` is only a
query parameter, a claim anyone can make (the handler's own comment at ~102–115
says so). `9df1d5ec` already removed `accessCode` from this branch for the same
reason.

**Required behaviour:**
1. The public route never returns `aiContext`, `briefing`, or any other
   decrypted org content that a player's phone does not need. Audit the whole
   `role === 'host'` branch and list in your report every field you kept and why.
2. The host's edit prefill gets those fields from an authenticated read:
   Cognito authorizer + `callerMayDriveSession`, 404 when refused. Precedent:
   `3ae0d2bd` ("GET /games/{gameId}/report is the host's read: Cognito, a
   named authorizer rule, callerMayDriveSession"). Choose one of two routes,
   whichever is smaller and clearer, and say why in the report:
   - a new route, such as `GET /games/{gameId}/host-details`;
   - a new `Auth` event on the existing handler at a different path.
3. The frontend caller(s) that read these fields (`GameHostPage.jsx` ~4522,
   the edit prefill; find any other reader of `aiContext`/`briefing` from this
   route, e.g. in `HostRemote.jsx` or setup dialogs) switch to the
   authenticated read via `authFetch`.

**Tests:** extend `tests/get-game-access-code.js` (or add a sibling). Anonymous
`?role=host` gets neither field. For the new read: an anonymous caller and a
caller from another org get 404, and the owning host gets both fields
decrypted. Add a frontend test that the edit prefill calls the new route with
auth. Check `tests/cors-allows-sent-headers.js` and any route-inventory tests
still pass.

### Task 2: A join code whose old rows still exist is not handed out again

**Bug (high, data mixing).** The only lock on a 4-digit code is the
conditional put of the `GAMES` reservation (`attribute_not_exists`,
`schema-compliant-manager.js` ~109–127), drawn in the loop at
`lambda-functions/websocket/create-game.js` ~221–289 (`MAX_ID_ATTEMPTS = 8`).
That reservation expires 7 days after start (`session-ttl.js`). But several
`GAME#<code>` rows live 30 days and say nothing about which session wrote them:
- `QUESTION#nnn#AISummary` (`get-ai-summary.js` ~1557);
- `PLAYER#x#SCORE` (`join-game.js` ~351–363, 30-day ttl);
- `REPORT`.

A code drawn again between day 7 and day 30 inherits those rows:
- the cached Workie summary is returned unchecked (`get-ai-summary.js` ~842–851);
- old SCORE rows join the leaderboard in the summary (~2100), the report
  (`create-report.js` ~113–116) and the scoreboard gate (`scoreboard.js` ~83);
- `report-merge.js` ~91 keeps the old snapshot's rounds.

Within one org, and from a platform session to anyone, the rows read cleanly.

**Required behaviour:** the draw treats a candidate code as taken when its
`GAME#<code>` partition still holds ANY row, even with no `GAMES`
reservation. Rules:
- Use a strongly consistent `Query` with `Limit: 1`.
- An item past its `ttl` but not yet deleted still counts as taken (DynamoDB
  deletes lazily). This is deliberate: say so in a comment.
- Order: check the partition, then make the conditional `GAMES` put. A second
  creator cannot write `GAME#` rows without first winning the `GAMES` put, so
  this order is safe. State that reasoning in a comment.
- The attempt cap and the honest 503 after it stay as they are.
- Do not add session stamps to rows. That is the fuller fix, deferred.

**Tests:** new `tests/code-reuse-isolation.js`:
- Seed stale `GAME#<code>` rows (a SCORE row and an AISummary row) with no
  `GAMES` row. Force the draw to offer that code first; the session is
  created under a different code, and the stale rows are untouched.
- Every attempt collides (partition rows or reservations): the result is the
  existing 503.
- An empty partition with no reservation is accepted on the first draw.

Arm the finish guard.

### Task 3: Closing an older round again neither rewinds the room nor scores twice

**Bug (medium).** `lambda-functions/game/get-results.js`:
- `enterResultsState` (~228–245) always writes `RESULTS#<old>` and
  `LessonNumber=<old>`, even when the session has moved past that round.
- The re-score guard (~675, ~958) compares only the player's latest scored
  round (`lastRound === paddedQuestionId`).

So closing round 3 and then round 2 again moves the whole room back to round 2
and awards round 2's points a second time. The likely trigger is a stale
second host screen: the stage plus the phone remote (`HostRemote.jsx`, which
polls).

**Required behaviour:**
1. A request to enter RESULTS for a round below `STATE.LessonNumber` changes
   nothing and answers with a clear refusal (409, or the status the file
   already uses for a stale transition). First check every caller of this
   path: stage, remote, redo, report. Confirm no legitimate flow re-enters an
   earlier round's RESULTS. If one does, report NEEDS_CONTEXT with what you
   found. Re-showing the CURRENT round's results must still work.
2. Scoring is idempotent per round. Record the rounds already scored on the
   score row (a set), so no round's points are awarded twice even if the
   transition guard is bypassed.

**Tests:** new `tests/reclose-round.js`:
- close 1 → 2 → 3, then ask for RESULTS of 2: state stays on 3, and no score
  changes;
- re-show the results of 3: allowed;
- scoring the same round twice through the scoring path adds its points once.

Update existing get-results suites only if they encoded the bug.

### Task 4: A host can end a trivia, poll, Call & Answer or wavelength session

pool runs dry (`next-question.js` ~1112, broadcasting as ~1117–1150). Surveys
have `survey/end`, and `hostControls.js` ~269 has `END_SURVEY` only. A host
who wants to stop after round 4 of 10 cannot, so the session stays live
until its ttl. The events feature also needs each item to end cleanly.

**Required behaviour:**
1. Add `POST /games/{gameId}/end`: Cognito + `callerMayDriveSession`, 404 when
   refused. It writes ENDED exactly as the pool-dry path does. Extract ONE
   shared helper from `next-question.js` and use it from both places. Do not
   duplicate the write or the broadcast.
2. The route is idempotent: an already-ENDED session answers 200 and writes
   and broadcasts nothing. A survey session is refused with 400 and pointed
   at `survey/end`, which stays unchanged.
3. The host gets an "End session" control:
   - add a host intent in `hostControls.js` beside the existing ones, used by
     the stage toolbar in `GameHostPage.jsx` and by `HostRemote.jsx` if the
     remote renders the same intents;
   - the control asks for confirmation first, in plain words: ending closes
     the session for every phone, laptop or tablet;
   - after it ends, the stage shows its existing ENDED screen (Session
     complete, podium, create report).

**Tests:** new `tests/end-session.js`:
- anonymous and other-org callers get 404;
- the owner ends the session: STATE and METADATA read ENDED, and the broadcast
  is sent;
- a second call is a no-op 200;

Frontend tests: the intent appears for a started non-survey session; confirm
